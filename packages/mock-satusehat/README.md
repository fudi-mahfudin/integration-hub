# Mock SATUSEHAT

A stateful, in-memory stand-in for the SATUSEHAT platform, used by the test suite, the big run and k6. **It has no authentication on `/__mock/*` and must never be deployed publicly**: it runs only in Vitest and in local/CI compose.

- Platform surface: `POST /oauth2/v1/accesstoken?grant_type=client_credentials`, FHIR under `/fhir-r4/v1`, KFA v2 under `/kfa-v2` (same token).
  - Create (validated): `Encounter`, `MedicationRequest`, `MedicationDispense`. Search: Patient/Practitioner by NIK, Location by `_id`, Encounter by `encounter/{org}`, MedicationRequest and MedicationDispense by `prescription/{org}` identifier; anything else is 400.
  - A MedicationDispense needs a contained Medication with a catalogue KFA 93 (else `KFA_LEVEL_INVALID`), a `context` Encounter and an `authorizingPrescription` MedicationRequest the mock holds (else `REFERENCE_NOT_FOUND`, rule 10394). Against that MedicationRequest's product: the same 93 or a child of its 92 is not a substitution, another 93 with the same 91 set is one, anything else is `UNSUPPORTED_THERAPEUTIC_SUBSTITUTION`; `substitution.wasSubstituted` must agree (`SUBSTITUTION_MISMATCH`), and a substitution needs a type, a reason and `responsibleParty`. Log `visitKey` via `context`, business identifier `prescription/{org}` (shared with the MedicationRequest, so fault counting per business identifier counts both).
  - A MedicationRequest must reference an Encounter the mock holds, else `400` with code `REFERENCE_NOT_FOUND`; its Medication must be contained (`medicationReference: {reference: '#id'}`) with a catalogue KFA 92/93 code (91 → `KFA_LEVEL_INVALID`) and quantity codes equal to the product's dose form. Its log `visitKey` is its Encounter's visit, its business identifier the `prescription/{org}` one.
  - KFA: `GET /kfa-v2/products?identifier=kfa&code=…` → `{ total: 1, result: { kfa_code, name, active, dosage_form {code,name}, product_template {kfa_code,name} | null, active_ingredients [{kfa_code, zat_aktif}] } }` from the world catalogue (plus `/__mock/seed` `kfaProducts`); unknown code → `404`. The envelope is assumed (no documented example).
- Inspection and control: `/__mock/*`, used only through `MockClient` (`@integration-hub/mock-satusehat`).
- Validation is the mock's own code (ADR 0006), stricter than the sandbox. It shares no code with the hub; `pnpm lint:boundaries` enforces that.
- Fixtures are typed builders in `src/templates/`, each tagged with its provenance (#16). Every value is fake.
- World dataset: `world/world.json`, regenerated with `pnpm world:generate` (sizes from `bigrun.commitments.json`).

Run standalone: `pnpm --filter @integration-hub/mock-satusehat start` (env: `MOCK_PORT` 4010, `MOCK_HOST`, `MOCK_WORLD_PATH`, `MOCK_TOKEN_EXPIRES_IN` 3599, `MOCK_TOKEN_THROTTLE_WINDOW_MS` 60000).

## Faults, holds and record mutation (#33)

- `PUT /__mock/faults` `{ seed, rules: [{ id, match: { method?, resourceType?, path? }, kind, rate | everyNth | firstN, params? }] }` replaces all rules and restarts their counters (`MockClient.setFaults`). `path` is exact, or a prefix ending in `*`; the token endpoint is matched by `path: '/oauth2/v1/accesstoken'`. `/__mock/*` is never faulted.
- Kinds and `params`: `http_500`, `http_401`, `http_503` / `http_429` (`retryAfter`: number = seconds, or with `retryAfterFormat: 'http-date'` an HTTP date that far ahead; string = sent verbatim; absent = no header), `http_400` (validation OperationOutcome, `rule` default `FAULT_INJECTED`, `code` default `PAYLOAD_INVALID`), `timeout` (held until the client hangs up, or `ms`, default 30000, then the socket is destroyed), `connection_reset`, `timeout_after_apply`, `http_500_after_apply`, `latency` (`ms`, or `minMs`/`maxMs`), `hold`.
- Rules are checked in order. Each matching rule counts the request per (rule, method, business identifier); a firing `latency`/`hold` delays and checking goes on; the first firing terminal rule ends it. So a later rule's `rate` is conditional on the earlier ones not firing: for exact shares set `rate_i = p_i / (1 - sum of earlier p)`.
- Decision = `faultDraw(seed, ruleId, method, key, nth) < rate` (exported). `key` is the business identifier (`encounter/{org}` system|value, resolved through the stored record for `/{type}/{id}`), else path + sorted query. Never server ids.
- Log: faulted requests carry `fault: <rule id>`; dropped or reset connections are logged with `response.status: 0`, when the client hangs up. Pre-apply faults have `effect: none`; after-apply ones keep the real effect.
- Holds: `GET /__mock/holds?wait=ms` long-polls for parked requests (`MockClient.nextHold(ms)`); `POST /__mock/holds/{id}/release` lets one carry on. Reset (and shutdown) drops parked requests unapplied and unlogged.
- Records: `POST /__mock/records` (insert as-is, `id`/`meta` assigned if absent), `PATCH /__mock/records/{type}/{id}` (JSON merge patch, bumps `meta.versionId`), `DELETE /__mock/records/{type}/{id}` (then `GET`/`PUT /{type}/{id}` → 404). Logged as `admin` entries, never submissions.
